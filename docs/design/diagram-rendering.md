# Diagram Rendering — 图数据到专业图表的确定性呈现

> 把编排事实、约束层级与契约依赖从图数据渲染为可复核的图表。图数据是唯一事实源，渲染器不创作内容。

## 1. 定位

执行逻辑已经以图形态存在：阶段节点与转移边（含回退环）构成状态机，阻塞点挂在边上，约束沿目录树继承，契约带上下游。此前这些结构只能靠阅读 YAML 与源码理解，文档侧以手写图承载理解结果——手写图与图数据之间没有任何到期校验，漂移不可见。

呈现层承担的职责是把"理解结果"变成图数据的确定性投影，从而：读者得到与实现同步的视图，评审者可用图判定编排完备性，文档内图示可被机器对账。

| 不是 | 原因 |
|------|------|
| 可视化编辑器 | 规范产物为 Markdown 与 YAML，不需要专用编辑器（既定非目标） |
| 由 LLM 现场绘制图示 | 固定执行逻辑不得由 LLM 发挥；图元与标签全部取自图数据 |
| 引入图形渲染二进制或绘图依赖 | 输出为文本形态图描述语言，渲染交给宿主与既有工具链 |
| 以图承载新事实 | 图是投影；任何只存在于图中的信息即缺陷 |

## 2. 四视图

| 视图 | 源数据 | 回答的问题 |
|------|--------|-----------|
| 阶段×阻塞点泳道 | 工作流 phases × phase_bps × 边上 blockingPoint | 代理在某阶段被什么把守、可走哪条边 |
| 状态机含回退计数 | PHASE_ORDER + PhaseEdge（forward/skip/backward/terminal）+ 变更 state 的 rollback/rebuild 计数 | 变更当前所处位置、剩余回退与重建预算 |
| 约束继承树 | SpecLayerContext 声明的层序与 inherited_from 继承链 | 约束沿哪一层进入本层、继承链在何处断裂 |
| 契约依赖图 | 契约实体的 upstream/downstream 与 criticality | 改这个接口影响谁、谁依赖它 |

四视图经 `mumuspec graph render --view <statemachine|lanes|contracts|constraints> --format <mermaid|dot|json>` 输出；MCP 侧的只读入口是 render_diagram 工具。两侧共用 `src/graph/facts.ts` 适配层——同一投影不得有两份实现。单条约束的归属与收紧明细仍由规范上下文命令给出，继承树只呈现层与链：把逐条来源塞进图会让图成为第二事实源。维度覆盖面的已覆盖与缺失清单由认知地图同步输出承载（其判定源为规范层覆盖面事实源），不在呈现层重复定义。

## 3. 确定性纪律

- 同一输入两次渲染字节一致：节点与边按稳定序输出，不使用哈希表遍历序。
- 标签只来自图数据：节点名、边说明、阻塞点描述、计数值均由源结构提供，调用方不得注入自定义字面量。
- 缺失即显式：无边可达的节点、未挂阻塞点的转移、无上游来源的约束必须在图上可见（以未把守样式标注），不得静默省略——省略等于把缺口画没。
- 方向语义保真：回退边必须与正向边在输出中可区分（含计数类别），否则状态机视图失去意义。
- 指标与阈值不写进图元：密度、比例类数值由命令与报告承载，图中只放结构与状态。

## 4. 输出格式

| 格式 | 用途 | 说明 |
|------|------|------|
| mermaid | 文档内嵌、宿主直接渲染 | 默认格式 |
| dot | 复杂依赖与大规模图的布局求解 | 仅输出源文本，不调用外部渲染器 |
| json | 程序化对账与测试断言 | 结构等价于源数据的规范化投影 |

格式枚举封闭：未知格式即参数错误并退出非零，不回落默认。

## 5. 与文档体系的关系

`docs/design/*.md` 内的图示属说明性内容，可手写；但文档中承载"当前实现如何"的结构事实 SHALL 与图数据一致。对账通道核对断言与事实的矛盾，不判断图好坏：

- 已接线（标识符层面）：文档审计比对阻塞点标识——文档中出现的门禁编号必须存在于工作流图数据（`workflow.default.yaml` 与项目级 override 的并集，当前 19 个），命中不到即报出。这防的正是"文档声称某门禁把守"而图里没有该门禁。
- 已接线（结构层面）：`docs/reference/workflow-diagrams.md` 是四视图的生成页，由 `src/graph/doc-page.ts` 从图数据投影而来（`npm run build` 重生成，变更状态不入页以免随阶段抖动）。`npm run docs:audit` 用同一投影比对已提交文本，不一致即报出首个差异行——承载"当前实现如何"的图示因此不再是手写第二事实源。
- 仍未接线（目标）：把散落在设计文档内的手写图描述块与投影做结构比对。图示块的布局性差异难以机器判定，且布局本不是事实载体，强行比对会把不可判定的东西伪装成门禁。
- 三项均为 WARN 起步、不阻断流程；升为 error 需先确认误报率并经人工签收。

## 6. 接入面

| 面 | 形态 | 约束 |
|----|------|------|
| CLI | 状态机图命令族的新增子命令（R-0019 接线） | 纯只读：不写状态工件、不触发阶段转换、可重复执行 |
| MCP | 只读工具，参数与 CLI 同源 | 遵守渐进披露预算：默认返回结构摘要，全量文本需显式请求 |
| 测试 | 字节比对与结构断言 | 语料声明聚合阈值，未声明的子目录不得静默丢弃 |

## 7. 错误处置

| 情形 | 处置 |
|------|------|
| 工作流配置缺段或不可解析 | 沿用既有 fail-safe：WARN 并回落内置默认，渲染在图注中标明所用来源 |
| 指定变更不存在 | 失败并列出活跃变更，不渲染空图 |
| 源数据自相矛盾（边指向未知节点） | 失败并指出矛盾点——呈现层不修复上游缺陷，也不代为掩盖 |

## Enforcement

- RENDER-1: 同输入字节一致性由测试锁定
- RENDER-2: 未把守边与无来源约束必须在输出中可见（反向用例）
- RENDER-3: 渲染输出与文档图块的结构对账纳入文档审计通道
- RENDER-4: manual(图样式与可读性由人工评审，机械通道只核对结构与来源一致性)
