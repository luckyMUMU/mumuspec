# Product Requirements: docs

## 模块职责
docs 目录是 MumuSpec 项目的文档中枢，按渐进式披露原则分层组织全部用户文档。
它提供从全局概览到架构层设计、操作参考、附录调研的完整文档体系，
帮助不同角色的用户（独立开发者、Tech Lead、AI 工具贡献者）快速找到所需信息。

## 存在理由
AI 编程工具与人类开发者都需要结构化的项目文档来理解设计意图、操作流程与约束边界。
散乱的文档会导致上下文过载或关键信息遗漏。docs 目录通过分层组织（Level 0-3）
将信息按读者深度递进排列，让读者只加载需要的层级，避免全量加载造成的 token 浪费。

## 用户场景
1. **新用户入门**：阅读 overview.md 了解核心目标与用户画像，30 分钟内理解项目定位
2. **实现者查阅设计**：进入 design/ 目录阅读六层架构设计文档，理解模块职责与接口
3. **操作者配置 CI**：进入 reference/ 目录查阅 CLI 命令、配置项、Phase Guard 规则
4. **深入了解者**：进入 appendix/ 目录阅读生态调研、对比分析、路线图等深度材料
5. **维护者更新状态**：更新 STATUS.md 的实现进度与反馈汇总，作为唯一权威进度来源

## 验收标准
- overview.md 是所有人首先阅读的 Level 0 入口文档
- STATUS.md 是项目进度的唯一权威来源，其他文档引用而非自行描述进度
- design/ 目录覆盖六层架构（Spec/Contract/Change/Knowledge/Guard/AI Integration）的设计文档
- reference/ 目录提供 CLI、MCP、配置、错误码等操作参考
- appendix/ 目录提供对比、调研、路线图等补充材料
- 文档间交叉引用使用相对路径，导航链接在每篇文档末尾标注
