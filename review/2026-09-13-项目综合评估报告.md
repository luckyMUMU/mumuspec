## 二、分模块详析

### 2.1 CLI 命令层（src/cli/，45 文件 ≈ 11,000 行）—— 7.5 分

**职责与结构**：`src/cli/index.ts`（486 行）`buildProgram()` 注册 45 个命令文件；命令层通用模式为 `findProjectRoot → loadConfig → 调 core 层 → 输出/exit code`，属正确的薄命令层设计。

**亮点**：
- `spec.ts:381-400` check 命令对 5 个漂移检测源逐源隔离，单源异常降级告警不崩整体。
- knowledge.ts 是 thin barrel 分发到 8 个子模块，职责拆分得当。

**问题**：
1. **init 业务逻辑整体泄漏命令层**（`cli/index.ts:111-434`）：12 个 Step 全内联 action，未下沉 core，MCP 无法复用。
2. **样板重复**：`"Not in a MumuSpec project"` 检查散布约 40 个文件 130 处；`process.exit(1)` 约 370 处，无统一 action 包装器。
3. **full drift report 双实现**：`spec.ts:517-549` 与 `mcp/tools.ts:880-910` 手写结构相同的聚合 JSON，易漂移。
4. **域逻辑入命令层**：`review.ts:68-97` 完整评分逻辑在命令文件内，且硬编码 `src/` 目录与排除规则。
5. **i18n 空壳**：`t()` 全库零调用，输出语言混杂（spec.ts 英文 vs state.ts 中文）。
6. **语义怪异**：`state.ts:176-179` E-CHANGE-007 打印 error 却 `exit(0)`。

**改进**：抽公共 action 包装器统一 root 校验/错误格式/`--json`；init 与 drift-report 聚合下沉 core；二选一处理 i18n（启用或删除）。

### 2.2 MCP 接口（src/mcp-server.ts + src/mcp/，≈ 1,300 行）—— 7.5 分

**亮点**：`mcp/tools.ts` 全部转调 core 层，与 CLI 无重复实现——单一权威源做得好；`tools.ts:497-531` 统一路径穿越校验；`mcp-server.ts:134-148` token 用 timingSafeEqual。

**问题**：
1. **CORS 回退隐患**：`mcp-server.ts:121-124` 未配置白名单时直接反射请求 Origin，注释称 "safe default" 实为放行任意来源。
2. **入参无运行时校验**：`args.x as string` 强转遍布（如 tools.ts:736-740），inputSchema 仅声明不执行；`default` 分支返回 error 对象而非抛错。

**改进**：入参加运行时 schema 校验；CORS 缺省改为拒绝并留日志。

### 2.3 core 核心（src/core/，46 文件 ≈ 12,000 行）—— 8.5 分

**职责与结构**：类型按域拆 8 个子模块；errors.ts 为 111 码/20 域注册表，是 guard 元数据单一权威源；constraint-evaluator 纯函数实现四步优先级；metrics/ 为注册表 + 6 个机械评估器。

**亮点（红线均落地）**：
- 约束密度 `defaultWeight: 0`（constraint-density.ts:79），注释明确"调节信号非进度分"。
- 六评估器全部机械采集，无 LLM 写指标路径；强度建议仅为咨询字符串且标注须人工签收。
- 权重单一权威源：各评估器 defaultWeight 唯一来源，激活权重和=1 由测试强制（types.ts:130-134）。
- `never` 穷尽性检查（constraint-evaluator.ts:191）；评估失败返回 nullResult 而非假满分。

**问题**：
1. **errors.ts 单体**：111 码一个对象字面量；`MumuSpecError` 未知码静默降级 ERROR（errors.ts:1230-1232），轻微 fail-open。
2. **grill-me 协议名实不符**：`canSelfCheck` 恒 false（grill-me.ts:712-719），头注释宣称的 "Fact self-check" 为死分支；skip 分支注释与代码矛盾（:610-613）。
3. **doc-importer 布尔优先级 bug**：`isFile && endsWith('.yaml') || endsWith('.yml') || endsWith('.md')`（doc-importer.ts:154），.yml/.md 目录误读；.openspec 目录仅收首个文件其余静默丢弃（:157）。
4. **指标采集代价高**：constraint-density/spec-compliance 每 scope spawn 一次 `npx mumuspec`（constraint-density.ts:91-98），有网络解析风险且 spawnSync 阻塞。
5. **注册表全局可变状态**：忘记调用 `registerBuiltInEvaluators()` 时 autoEvaluate 报 "All evaluators failed"，注册遗漏与真实失败不可区分。
6. 小问题：git.ts:122-124 `git add -A` 结果被忽略且 commit allowFail；html-reporter 阈值 0.85 硬编码与 DEFAULT_CONVERGENCE_CONFIG 重复。

**改进**：errors.ts 按域拆分；修 doc-importer 括号优先级；metrics 改进程内 API 调用替代 npx 自举；注册表改构造注入。

### 2.4 变更生命周期（src/change/，18 文件 ≈ 5,200 行）—— 8.5 分

**亮点**：
- 状态机为有向环图实现，支持项目级 workflow.yaml 注入；backward 边区分 rollback/rebuild 双计数上限。
- **DeltaMergeResult 三态 fail-closed 到位**（archive.ts:383-390）：unresolved 由 `archiveChange` 以 E-CHANGE-022 中止归档并留 audit（:186-201）。
- worktree 清理失败、changelog 写失败等 fail-open 路径均落 audit。

**问题**：
1. **约束合并非 fail-closed 且无留痕**：`mergeConstraintsToScope` 整体 try/catch "Non-fatal" 静默（archive.ts:560-562）；`mergeChangeLevelSpecs` 失败仅写 mergeLog，而 mergeLog 汇总 audit 一律记 `result:'success'`（:504-512）——**失败事实被 success 掩盖，与 delta 合并纪律双标**。
2. **escalateChange 状态分裂风险**：目录搬运 catch 静默（lifecycle.ts:324-326）后仍写 success audit。
3. 脚手架失败无痕（lifecycle.ts:200-202）、升版失败返回 null 无 audit（archive.ts:95-97）。
4. 中部 import（archive.ts:35、:297-298）反映文件过长后的补丁式维护。

**改进**：统一非致命路径留痕纪律（各补 audit 或并入 unresolved 语义）。

### 2.5 守卫层（src/guard/ + src/hooks/，16 文件 ≈ 4,070 行）—— 8.0 分

**亮点**：
- E-GUARD-010 通道判定在 build_to_verify 硬阻断无通道 delta 约束（phase-guard.ts:750-759）。
- 词法通道单一权威源基本成立：`isRegexCheckable` 被 delta-channels/checker 复用。
- phase-guards.md 声明"下表即实际输出"并自曝缺口——文档-代码对齐罕见地诚实。

**问题**：
1. **词法通道局部漂移**：checker.ts:723-736 手工复制 `extractRegexPatterns`（注释自认 "mirrors"）；:681 的 jsx/tsx 判断重复 isRegexCheckable 逻辑——与"单一权威源"目标相悖。
2. **flexible edges 稀释状态机刚性**：`resolveEdge` 合成任意非终态间边（state-machine.ts:96-99），显式 DCG 边约束名存实亡，门禁实际全押 phase-guard。
3. checker.ts（1199 行）混杂扫描/分类/折叠/drift 四种职责；phase-guard.ts 含 markdown 解析辅助（:691-700）。
4. 小瑕疵：`canRollback` rebuild 超限把 E-CHANGE-003 放 warnings 却返回 passed:false（state-machine.ts:377-388）。

**改进**：eval/jsx 判定收编进 verifier-classify 导出；收紧 flexible edges 或文档显式声明豁免范围；拆分 checker.ts 解析辅助层。

### 2.6 规范层（src/spec/，11 文件 ≈ 3,030 行）—— 8.0 分

**亮点**：
- `stripFencedBlocks` fail-closed：未闭合围栏丢弃至 EOF（parser.ts:53）。
- 四分类固定次序，词法正则与 guard/checker 共享单源（verifier-classify.ts:85-112）。
- 序列化 round-trip 保真（parser.ts:198-234）；W-SPEC-016 词表语料 0 噪音。

**问题**：
1. **fail-open**：损坏的 tech.md/spec.md 仅记日志跳过，prohibitions 静默缺失（loader.ts:62-66、81-85）。
2. **继承冲突检测次序可疑**：先 merge 再 detect（loader.ts:224-231），子层已含父层条目可能自冲突误报；且重复读盘解析（:215-222）。
3. **死代码**：index.yaml 新鲜度检查计算 `actualChildren` 后无任何动作（validator.ts:69-78）。
4. 词表仅 7 个中文限定词，英文 unbounded 词未覆盖；节标题 `startsWith('### SHALL')` 可误吞 `### SHALLXYZ`（parser.ts:129）。

**改进**：解析失败上抛或计入 GuardResult；冲突检测移到 merge 前并缓存；删死代码。

### 2.7 契约层（src/contract/，9 文件 ≈ 2,560 行）—— 7.0 分（本组最低）

**亮点**：AST 分析器用 TS Compiler API 实现规范；注册表校验含原型污染防护（loader.ts:33-82）；锁超时抛错不静默绕过（manager.ts:94-95）。

**问题**：
1. **红线违规——checker/builder 双实现**：脚手架走 AST 递归扫描（manager.ts:446-475），而校验端 `verifyExportExists` 仅扫目录第一层且用 `content.includes(name)` 子串启发式（validator.ts:381-397）。**嵌套目录的导出必误报 E-CONTRACT-002；名字出现在注释/字符串则漏报**。这是本次评估发现的最严重正确性缺陷。
2. **并发缺陷**：`persistContract` 先读 registry 后加锁（manager.ts:109-117），锁不防丢更新；锁等待为 CPU 忙等自旋（:87-90）。
3. 清单重复：`REGISTRY_FILES` 与 `discoverContractDirs` 各自硬编码三文件可漂移。
4. `isPotentiallyConflicting` 与 inheritance.ts 启发式近似并存。

**改进（优先级最高）**：validator 改调 ast-analyzer 递归 AST，消除双实现；锁改 Atomics.wait 或退避；清单统一到 constants.ts。

**改进**：ID 改持久化计数或内容哈希；合并 doctor/organize 检测逻辑；补两文件测试。

## 四、优化建议（按优先级）

### P0 —— 正确性缺陷（建议本迭代内修复）

1. **contract validator 双实现**：`verifyExportExists`/`verifyDependencyUsage` 改调 ast-analyzer 递归 AST，消除嵌套目录误报 E-CONTRACT-002 与子串漏报（红线：checker 与 builder 不得双实现）。
2. **doc-importer 布尔优先级**：`isFile && (endsWith('.yaml') || endsWith('.yml') || endsWith('.md'))`。
3. **git-scanner ID 重复**：计数器改持久化或内容哈希派生。
4. **约束合并留痕**：mergeConstraintsToScope / mergeChangeLevelSpecs 失败须入 audit 且不得记 `result:'success'`；escalateChange 搬运失败须中止或显式留痕。

### P1 —— 纪律与安全加固

5. **CORS 缺省改拒绝**（mcp-server.ts:121-124）；MCP 入参加运行时校验。
