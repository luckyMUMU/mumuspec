## 二、变更清单

工作流判定口径：涉及 `.mumuspec/` 规范文件（BOUNDARY/tech/spec）或引擎契约者为 `hotfix` 语义（携带 delta-spec）；纯引擎实现修正走 `hotfix`；新增错误码需注册 `ERROR_CODES`。所有批次完成后必须 `node scripts/regen-rules.mjs` + 版本对齐 + `ci:check` 绿。

### 批次 A｜契约边界可信化（最高优先，含现网失效）

**A1 `contract-boundary-soundness`（hotfix）**

- 目标：`contract boundary check` 的判定既可解释又不误伤，退出码回归 severity 契约。
- 修法：
  1. `validator.ts` 的导出/依赖校验改调 `ast-analyzer.ts` 的递归 AST 结果（`analyzeExports` 已支持 function/class/const/interface/type/default/re-export），删除 `verifyExportExists`/`verifyDependencyUsage` 两个启发式——**同时消除"checker 与 builder 双实现"红线违规**。
  2. `findDirectoriesWithCode` 增加默认排除集 `dist/ build/ coverage/ out/ .next/ temp/`（内置常量，不加配置项）。
  3. `contract.ts` 展示层改按 `err.severity` 选择 `[ERROR]/[WARN]` 标签与计数，仅 severity=ERROR 时 `exit(1)`。
- 验收：
  - `contract boundary check` 在本仓库对 `src/**` 输出 0 ERROR（BOUNDARY 修复后），且不再出现 `dist/**`、`tests/**` 条目；
  - 新增单测：①嵌套子目录中的真导出判定通过；②仅在 import 行出现的名字**不得**免检（反向用例）；③WARN 级问题不改变退出码。
- 影响文件：`src/contract/validator.ts`、`src/cli/commands/contract.ts`、`tests/contract/*`。
- 风险：AST 分析对 `.vue`/`.py`/`.go` 等非 TS 扩展名无覆盖（现启发式对所有扩展名生效）→ 修法保留"非 TS 家族扩展名回退到文本判定"的分支，并在 BOUNDARY 注记覆盖边界。

**A2 `boundary-doc-drift-fix`（hotfix）**

- 目标：消除 10 条真阳性。
- 修法（逐条裁决，不搞批量删）：
  | 模块 | 声明 | 处置 |
  |---|---|---|
  | src/bundle | `ValidationResult` / `BundleInfo` / `CreateBundleOptions` | 改为实际名 `ManifestViolation` / `BundleManifest` / `BuildPluginPackageOptions`（或删除，视是否为对外承诺） |
  | src/change | `ChangeInfo` / `PhaseNode` | 删除（现网对应 `ArtifactData` / `PhaseEdge`+`PhaseGraph`） |
  | src/cli | `registerAllCommands` | 删除（现为 `buildProgram` + `registerXxxCommand` 系列） |
  | src/contract | `ContractCategory` / `ContractCriticality` / `ContractStatus` | 二选一：①改注为"依赖 `core/types-contract.ts`，非本模块导出"；②若确为对外承诺则在 `src/contract/index.ts` 补 `export type {…} from '../core/types-contract.js'` |
  | src/knowledge | `ExtractedSymbol` | 同上一行二选一 |
- 验收：`contract boundary check` 的 E-CONTRACT-002 归零；`BOUNDARY.md` 变更日志补条目。
- 注意：改 `.mumuspec/BOUNDARY.md` 后必须 `regen-rules.mjs`（E-AGENTS-001）。

### 批次 B｜审计与 fail-open 收口（纪律面）

**B1 `merge-audit-honesty`（hotfix）**

- 修法：`mergeChangeArtifacts` 的汇总 audit 依据 mergeLog 内容判定 `result: 'success' | 'failed'`，失败时补 `error` 字段；`mergeConstraintsToScope` 的空 catch 改为向 mergeLog 注入失败行。
- 验收：单测断言"目标 spec 写入失败 → audit.result === 'failed' 且 summary 含原因"；不再存在 result 与 summary 语义相反的组合。

**B2 `spec-load-fail-closed`（hotfix，需裁决 D2）**

- 修法：`spec/loader.ts` 三处解析失败不再静默——收集为 `loadDiagnostics`，由 `validate`/`check` 以既有不可验证通道暴露（优先方案，避免直接 throw 破坏只读命令的可用性）。
- 验收：故意写坏 `src/spec/.mumuspec/spec.md` → `mumuspec validate` 报出可见诊断而非 0 约束静默通过。

**B3 `doc-importer-fix`（hotfix）**

- 修法：括号优先级修正；`.openspec` 目录改为全量收录（保持与多文件预期一致）。
- 验收：新增 `.yml`/`.md` 目录与同目录多文件两条单测。

### 批次 C｜诚实性与安全（用户可见面）

**C1 `team-simulation-labeling`（hotfix，需裁决 D4）**

- 修法：`team run` 输出显著标注模拟性质（如 `[SIMULATED] … 分数由 MockRuntimeAdapter 生成，不代表真实评估`），并在 `--json` 产出中带 `simulated: true`；或在真实 adapter 落地前要求显式 `--simulate` 才可执行。
- 验收：单测断言 stdout/JSON 含模拟标记。

**C2 `mcp-hardening`（hotfix）**

- 修法：①CORS 缺省不写 `Access-Control-Allow-Origin`（同源默认，注释与行为对齐）；②工具入参在 `callTool` 入口做运行时校验（复用现有 schema 声明，缺字段即返回结构化 error 而非 `as string` 强转）。
- 验收：缺 `MUMUSPEC_MCP_CORS_ORIGIN` 时响应不含 ACAO 头；缺参调用返回明确错误。

### 批次 D｜结构优化（可延后）

**D1 `cli-action-wrapper`**：抽公共 action 包装器统一 root 校验 / 错误格式 / `--json`，覆盖 109 处 root 检查与 322 处 `process.exit`；init 的 12 Step 下沉 core 另立一变更。
**D2 `errors-split`**：`errors.ts` 按 20 域拆分子文件 + 聚合桶；未知码构造时告警。
**D3 `metrics-inprocess`**：评估器从 `npx` spawn 改为进程内 API 调用（消除网络解析与阻塞）。
**D4 `lexical-single-source`**：`checker.ts` 的 eval/jsx 手工判定收编进 `verifier-classify`。
**D5 `test-consolidation`**：40 个平铺测试归入域目录、合并 `-extraN` 碎片；补 `memory.ts`/`conversation.ts`/`team.ts` 盲区。

### 批次 E｜死端与潜伏缺陷

**E1 `experiment-mode-gating`（需裁决 D5）**：为 `loop experiment` 加 experimental 标注 + 门禁，或从 CLI 摘除（引擎保留封存）。
**E2 `scanner-id-stability`**：scanner ID 改内容派生态（对同一发现稳定、跨会话不撞）；因当前无落盘路径，可与 E1 合并排期。
**E3 `cleanup-temp-decision`**：实现 temp 清理并接入 archive 收尾（补 TEMP-4 红线支撑），或删除空文件并在规范层明确该红线由人工承担——二选一，不留中间态。
**E4 `skill-authoring-validate`**：`validateSkill` 从"文件存在 + `#` 开头"提升到结构校验（frontmatter 必填字段、name/description 约束）。

## 五、边界（本计划不做）

- 不动 composite 权重、阈值与 `constraint_strength`（红线同源）。
- 不为外围死端补功能实现（experiment 接通、team 真实 adapter）——只做诚实性收敛。
- 不重构 `change/state-machine.ts` flexible edges、不拆分 `guard/checker.ts`（改动面大，另立专题）。
- 不引入新依赖、不新增配置项（A1 排除集用内置常量）。
