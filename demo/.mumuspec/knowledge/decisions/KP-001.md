## 决策背景

Task API 需要构建 HTTP 服务，面临框架选择：使用 Express 等成熟框架还是 Node.js 原生 http 模块。

## 决策

使用 `node:http` 原生模块，不引入 Express。

## 理由

根据 Ponytail 7 级优先级阶梯：

1. **Level 3 (标准库)**: Node.js 原生 `http` 模块完全满足 REST API 需求
2. **Level 1 (YAGNI)**: Express 提供的中间件系统、模板引擎等功能未被请求
3. **Level 5 (已有依赖)**: 零依赖，减少包体积和安全攻击面

## 代价

- 需要手动解析 URL 和请求体（约 20 行代码）
- 没有中间件生态系统

## 适用范围

- 小型 API 服务（< 20 路由）
- 对依赖体积敏感的场景
- 学习/演示项目

## 不适用场景

- 大型生产应用（建议使用成熟框架获得更好的可维护性）
- 需要 WebSocket/SSE 等高级协议的场景
