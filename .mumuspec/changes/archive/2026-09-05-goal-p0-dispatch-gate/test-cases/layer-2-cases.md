# Test Cases - Layer 2: AGENT_RULE_TARGETS 声明表 + rules-generator 纯函数

> 测试文件：`tests/rules-generator.test.ts`
> 被测模块：`src/install/installer-registry.ts`（改：+4 AgentType、AGENT_RULE_TARGETS）、`src/install/rules-generator.ts`（新，纯函数无 IO）

## Cases

### TC-A2: CLAUDE.md 薄壳首行 === `@AGENTS.md`
- **可验证性**: enforced-strong
- **Given**: 规范上下文（规范链摘要 + Ponytail 约束 + CLI 速查 + MCP 入口）
- **When**: `renderRuleFiles('claude', ctx)`（或等价表驱动入口）
- **Then**: 返回 `{ path: 'CLAUDE.md' }` 项，content 首行严格等于 `@AGENTS.md`（无前导空行/空白）；第二行起为薄壳说明（≤3 行）。
- **子断言**: AGENTS.md 生成物含标记头 `> Auto-generated by MumuSpec. Do not edit manually.` 且 ≤200 行。

### TC-A3: 冲突三态判定 + --force-rules 覆盖
- **可验证性**: enforced-strong
- **Given**: 内存态文件表（无 IO）
- **When/Then**:
  1. 文件不存在（absent）→ `action: 'create'`
  2. 文件存在且含 MumuSpec 标记头（managed）→ `action: 'update'`
  3. 文件存在且无标记头（user）→ `action: 'skip'` + 诊断 warn（不产出内容覆盖）
  4. user 冲突 + `forceRules: true` → `action: 'update'`（接管，诊断记录 force）
  5. 三态对 AGENTS.md 与 CLAUDE.md 独立判定（一个 user 不影响另一个 update）
- **断言补充**: `skip` 项不得携带将落盘的 content（防止调用方误写）。

### TC-A5: 表驱动冒烟 — 新增 agent 零渲染逻辑改动
- **可验证性**: enforced-strong
- **Given**: AGENT_RULE_TARGETS 中既有 4 个真实目标（codex/windsurf/copilot→AGENTS.md，claude→AGENTS.md+CLAUDE.md 桥，gemini→AGENTS.md+GEMINI.md 桥）
- **When**: 对表中每个 agent 执行 `renderRuleFiles(agent, ctx)`
- **Then**: 每个 agent 至少产出 1 个 rules 文件计划；所有桥文件首行规则成立（CLAUDE.md→`@AGENTS.md`，GEMINI.md→`@AGENTS.md`）；无 agent 触发渲染分支 if/switch 扩展（结构性断言：渲染函数签名与分支数不变，可导出目标表遍历）。
- **子断言**: 目标表不含 `.cursorrules` / `.windsurfrules`（D2 红线，字符串级扫描表内容）。

## 边界与不变式
- rules-generator 纯函数：相同输入必产相同输出；无 fs/path 之外的副作用，无网络。
- AGENT_RULE_TARGETS 是规则目标唯一持有处：新增 agent 只改表不改渲染逻辑。
- 生成内容契约：AGENTS.md = 规范链摘要 + Ponytail 约束 + CLI 速查 + MCP 入口指引。
