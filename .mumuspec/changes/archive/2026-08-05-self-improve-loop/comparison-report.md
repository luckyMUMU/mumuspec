## 2. 方向 A: 增强 Drift 检测（自动修复建议）

### 2.1 实现内容

位置: `src/guard/checker.ts`, `src/cli/commands/spec.ts`, `src/core/types-workflow.ts`

新增功能:
1. `--fix` 参数: 安全自动修复 drift（只修复 WARN 级别）
2. `--dry-run` 参数: 预览修复效果，不实际应用
3. `fixHint` 字段: 对无法自动修复的 drift 给出提示
4. 幂等性: 通过标记防止同一 drift 被重复修复
5. `autoFixDrift()` 函数: 独立的可复用模块

### 2.2 评估

| 维度 | 评分 | 说明 |
|------|------|------|
| 实现复杂度 | 2/5 | 逻辑清晰，主要增加新的 CLI 选项和处理函数 |
| 用户价值 | 4/5 | 高频场景，drift 是常见需求，自动修复大幅减少手动操作 |
| 向后兼容性 | 5/5 | 纯新增功能，不影响现有 `mumuspec drift` 调用 |
| 维护成本 | 2/5 | 代码量小 (<100行)，逻辑简单，易于维护 |
| **综合推荐** | ✅ **推荐引入** | 高价值低风险 |

### 2.3 收获

- `--fix` 的 "安全修复" 原则: 只处理 WARN，不碰 ERROR，避免自动化破坏
- 幂等性设计: 通过文件中标记而非状态机，简化实现
- `fixHint` 字段: 告知用户手动操作步骤，即使无法自动修复也有帮助

### 2.4 后续可优化

- 真正的 enforcement 模板生成（而非仅添加注释）
- 批量修复模式 (auto-select safe fixes)
- undo 功能（回滚已应用的 fix）

## 3. 方向 B: Worktree 智能管理

### 3.1 实现内容

位置: `src/core/loop-engine.ts`, `src/cli/commands/loop.ts`

新增功能:
1. **Bug 修复**: 移除 `ensureDir` + `git worktree add` 冲突（Windows 上目录预创建导致 git 失败）
2. **`loop cleanup` 命令**: 自动清理已合并的 loop worktree
3. **增强的 worktree 解析**: `parseWorktreeList()` 结构化解析 porcelain 输出
4. **分支合并检测**: `checkBranchMerged()` 判断分支是否已合并

### 3.2 评估

| 维度 | 评分 | 说明 |
|------|------|------|
| 实现复杂度 | 3/5 | 涉及 git 操作和字符串解析 |
| 用户价值 | 3/5 | 解决实际 bug (worktree 创建失败)，cleanup 是实用功能 |
| 向后兼容性 | 4/5 | cleanup 是纯新增命令；worktree bug fix 改变错误处理流程 |
| 维护成本 | 3/5 | git 操作需要关注跨平台兼容性 |
| **综合推荐** | ✅ **推荐引入（部分）** | bug fix 必须引入，cleanup 作为可选增强 |

### 3.3 收获

- Windows 上 `git worktree add` 对已存在目录敏感，不能预创建
- `git branch --merged HEAD` 是检测合并状态的好方法
- `--porcelain` 输出适合机器解析

### 3.4 后续可优化

- worktree 复用机制（同分支不重复创建）
- 自动 cleanup 集成到 `loop exit` 或 `loop merge` 流程
- worktree status 更丰富的展示

## 7. Loop 模式本身的反思

### 优点
- 强制结构化思考（每轮有 plan → act → evaluate）
- 自动 commit 保证每轮产出可回溯
- worktree 隔离确保实验安全
- 收敛标准驱动避免无限优化

### 可改进点
- 默认 3 轮对探索性任务略少（可考虑初期 5 轮）
- 自动修复逻辑的"安全边界"可进一步明确
- worktree 创建 bug 暴露了 Windows 兼容性测试缺口
- 缺少"观察日志"机制——难以跨轮对比
