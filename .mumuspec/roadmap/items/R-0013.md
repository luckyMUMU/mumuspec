# R-0013: JIT 式按 target 加载与反向通道

## 背景

> 为什么需要这个目标？当前痛点是什么？不做的后果？

差距分析（nl-bytecode-gap-analysis-2026-08-29.md，DSL 定位修正后）两项 P2：① 渐进披露按目录链加载（root+parent+target ≤3 层），与"本次要动的代码"无关——应支持按 target 查询 GOVERNED_BY 绑定只拉相关约束子集（code graph 的 spec binding 已有 MVP，graph-builder.ts:246-299）；token 预算靠层数/页数启发式而非显式计量；② 代码→spec 的反向通道（BOUNDARY sync、归档知识提取）是雏形，GOVERNED_BY 绑定未接入 drift 检测——spec 的 target 变了而代码未动的情况不可见。

## 范围

### 包含（Includes）
- `mumuspec context` 新增按 target 查询：`--target <file>` 时以 GOVERNED_BY 绑定为主入口返回受管约束子集（目录链加载保留为 fallback）
- token 预算显式计量：context 输出附带 token 估算（替代/补充层数≤3、页数≤5 启发式，阈值可配置）
- GOVERNED_BY 绑定接入 drift 检测：spec target glob 命中的文件集变化而 spec 未更新 → 绑定类漂移（新 WARN 类别）
- 绑定持久化从内存 Map 升级为可增量更新的存储（现有 JSON 序列化基础上；config 中 `storage: sqlite` 声明与实现的差异一并修正为实际形态）

### 不包含（Excludes）
- tree-sitter 多语言图谱扩展（R-0003 框架上的独立扩展）
- 跨仓库图谱
- 实时文件监听（drift 仍走 CI/命令触发）

## 验收标准（DoD）

| # | 验收条件 | 验证方法 |
|---|---------|---------|
| 1 | `context --target <file>` 返回的约束子集与该文件 GOVERNED_BY 绑定一致 | fixture 仓库集成测试 |
| 2 | context 输出含 token 估算，且预算阈值可配置生效 | 配置项单元测试 |
| 3 | 绑定类漂移：修改 spec target glob 后未更新代码 → drift 报 WARN；误报率 <5%（dogfooding 实测） | dogfooding `check` 实测 + 统计 |
| 4 | config.yaml 中 code_graph storage 声明与实现一致 | 文档与代码走查 |
