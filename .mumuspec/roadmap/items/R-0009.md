# R-0009: skill↔CLI 引用一致性校验

## 背景

> 为什么需要这个目标？当前痛点是什么？不做的后果？

2026-08-29 盘点发现 6 处 skill↔CLI 不一致（2 个状态机不存在的目标 `verify-fail`/`archive-reopen`、1 个缺 `--confirm` 的必拒调用、1 个缺 `--text` 的必拒调用、1 段过时的 Guard/State 说明、1 个 spec 承诺但从未实现的命令）。根因：**spec 有 drift 检测，skill 文本没有任何与实现的一致性机制**。不做的后果：LLM 照 skill 执行必失败的命令，流程中断且难排查。

## 范围

### 包含（Includes）
- 从 commander 注册表生成「命令面清单」：命令路径、参数签名、目标阶段枚举、`--confirm`/必填项要求（复用 error-codes-doc 的自动生成模式）
- 校验器扫描 `skills/**/*.md` 中的 `mumuspec ...` 命令引用：面外命令、无效目标阶段、不可逆调用缺 `--confirm` → 报错
- 接入 `npm run enforce` / `ci:check`（错误码文档同款防漂移位）
- spec.md CAP 块的 CAP-DESC-2「能力元数据与代码实现一致（CI 校验）」可经此机制部分兑现

### 不包含（Excludes）
- 自然语言语义校验（只校验命令面与参数形状）
- 非 mumuspec 命令引用（git/gh 等）

## 验收标准（DoD）

| # | 验收条件 | 验证方法 |
|---|---------|---------|
| 1 | 校验器对本仓全部 skills 运行为绿（存量已清偿） | `npm run enforce` 通过 |
| 2 | 注入无效命令引用（如 `state transition <n> verify-fail`）能被检出并给出修正建议 | 回归测试（fixture 注入） |
| 3 | 生成命令面清单可人工审阅（文档化输出） | 清单文档落盘 |
