# R-0012: 工作流薄封装

## 背景

> 为什么需要这个目标？当前痛点是什么？不做的后果？

2026-08-29 盘点中两类 D1（薄封装）缺口：① worktree/分支创建是 phase-open Step 6 与 BP-11 的手工 `git worktree add`/`git branch`（仅 branch-driven 配置下 `new` 自动建分支，lifecycle.ts:59）；② 归档子流程 A 的 push/建 MR/CI 触发全是手工 git/gh。这些是确定性操作，LLM 手工执行既慢又易错（降级路径 Fallback C 本身就是为"命令不存在"打的补丁）。

## 范围

### 包含（Includes）
- `mumuspec isolation create <name> --mode worktree|branch [--name <branch>]`：复用 core/git.ts 既有函数（createBranch/getWorktreePath）；分支命名默认规则 + `--name` 覆盖（BP-11 的用户确认仍走交互，不自动化）
- `mumuspec isolation clean <name>`：归档后 worktree/分支清理（removeWorktree/deleteBranch 已有）
- 归档 push/MR 触发命令：检测 gh 可用性，不可用输出手工指令（降级而非失败）；默认 dry-run

### 不包含（Excludes）
- MR 描述生成（LLM 决策域）
- CI 结果等待/轮询（宿主环境职责）
- 隔离策略变更（worktree/branch 语义维持现状）

## 验收标准（DoD）

| # | 验收条件 | 验证方法 |
|---|---------|---------|
| 1 | open Step 6 的手工 git 操作被命令替代，Fallback C 保留为降级路径 | skill 文本更新 + 命令集成测试（临时仓库） |
| 2 | 归档 push/MR 命令 dry-run 输出与实际执行一致；gh 缺失时输出手工指令并 exit 0 | 环境缺失模拟测试 |
| 3 | 清理命令与 archive/finalize-archive 的既有清理行为幂等兼容 | 重复执行测试 |
