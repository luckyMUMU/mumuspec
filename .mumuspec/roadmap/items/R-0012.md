# R-0012: 多模型自适应约束强度

## 背景

> 当前约束强度系统（Constraint Strength 0.12.x）仅按"项目级双维度三档"调节，无法区分**执行约束的模型能力层级**。
> 这导致一个关键痛点：同一个项目，使用者切换到更便宜/更快的模型时（如从 Claude Sonnet → Haiku，或 GPT-5 → GPT-4o-mini），
> 约束强度仍为同一档位——要么对新模型过严（浪费推理 token），要么对新模型过松（产出质量下降）。
>
> 核心洞察：**约束的本质是弥补模型的能力缺口**。能力越强的模型，需要的外部约束越少；
> 能力较弱的模型，需要更严的约束来兜底产出质量。
>
> 竞品参考：
> - Cursor 的 "Turbo Mode" 在快速模型上自动松弛约束
> - Cline 的模型切换 + guardrail 层在弱模型上强制更多验证步骤
> - Claude Code Dynamic Workflows 的 Agent 模型选择影响流程深度
>
> 本目标与 R-0004（LLM 自由度工作流）互补：R-0004 是"LLM 主动参与流程决策"，
> R-0012 是"框架根据模型能力自动调节被动约束"。
> 两者合并为 Model-Adaptive Harness（模型自适应框架）的终极愿景。

## 范围

### 包含（Includes）
- **模型分层体系（Model Tier System）**：4 个能力层级（S/A/B/C），每个层级对应不同的约束强度偏移
- **项目基线 + 模型偏移的复合求值**：`effective_strength = modulate(project_strength, model_tier)`
- **约束文件的 `model_tier_overrides` 条目**：允许项目对特定维度做模型感知覆盖
- **Auto-detect 机制**：从环境变量 / Agent 上下文 / CLI 参数自动识别当前活跃模型层级
- **CLI 可见性**：`mumuspec constraints resolve --show-model-tier` 输出当前有效强度矩阵
- **求值链路升级**：`evaluateConstraint()` 引入 `modelTier` 参数
- **约束强度叠加规则文档**：清晰定义"项目基线 vs 模型偏移 vs 例外清单"三层优先级

### 不包含（Excludes）
- **多 Agent 混合编排**（R-0006 的范围，每 Agent 独立选模型属于后续）
- **运行时 LLM 权重微调**（不改变底层模型能力）
- **基于实时输出质量的动态升降级**（过于复杂，留作 R4 长期愿景）
- **跨语言约束分析扩展**（仅 TypeScript 生态先行）
- **各 IDE Agent（Claude Code / Trae / Cursor）的差异化配置文件**（保持 CLI 单一事实源）

## 设计概述

### 模型分层（4 Tier）

| Tier | 典型模型 | 能力特征 | 强度偏移 | 效果 |
|------|---------|---------|---------|------|
| **S** | Claude Sonnet 4, GPT-5 | 最强推理 + 长上下文 + 多步规划 | -1（放宽一档） | high→medium, medium→low |
| **A** | Claude 3.5 Haiku(复杂任务), GPT-4o | 中等推理 + 较快 | 0（基线） | 不变（项目设定值） |
| **B** | Claude 3 Haiku, GPT-4o-mini | 较快推理 + 易跳过步骤 | +1（收紧一档） | medium→high, low→medium |
| **C** | 本地小模型 ( Ollama/LM Studio ) | 有限推理 + 需强制约束 | +max（强制 high） | 全部维度 clamped to high |

### 强度调制公式

```typescript
// Pseudocode
function modulateStrength(
  baseline: ConstraintStrength,   // 项目配置值: 'high' | 'medium' | 'low'
  tier: ModelTier,                // 'S' | 'A' | 'B' | 'C'
  exceptionList: string[],        // 始终阻断的约束 ID 集合
  constraintId: string,
): ConstraintStrength {
  // 例外清单：任何 Tier 都始终 high
  if (exceptionList.includes(constraintId)) return 'high';

  // C-Tier：强制最高强度（不放宽）
  if (tier === 'C') return 'high';

  const rank = { low: 1, medium: 2, high: 3 };
  const delta = { S: -1, A: 0, B: 1, C: Infinity };
  const levels = ['low', 'medium', 'high'];

  const effective = Math.max(1, Math.min(3, rank[baseline] + delta[tier]));
  return levels[effective - 1] as ConstraintStrength;
}
```

### 三层约束优先级

```
优先级（高 → 低）：
1. 例外清单（always_enforce） — 不可被 Tier 降级
   ↓
2. 项目显式 overrides（config.yaml: constraint_strength.overrides.*）
   ↓
3. Tier 调制后的有效强度
```

### 配置扩展

```yaml
# .mumuspec/config.yaml 新增段落
constraint_strength:
  technical_design: medium       # 项目基线
  requirement_goals: high
  exceptions: [...]              # 不可降级清单

  # 段落：模型感知配置（新增）
  model_tier:
    active_tier: 'A'             # S | A | B | C；缺失则默认 A
    auto_detect: true            # 从环境变量 / Agent 上下文自动检测
    # 可选：每模型显式映射（覆盖 auto_detect）
    model_map:
      'claude-sonnet-4-20250514': 'S'
      'claude-3-5-haiku-20241022': 'A'
      'gpt-5':  'S'
      'gpt-4o': 'A'
      'gpt-4o-mini': 'B'
    # 可选：在特定约束 ID 上禁用 Tier 调制（始终用项目基线）
    disable_modulation: ['RG-SHALL-NOT-002']  # 如"禁止 AI 自动发起 Discard"
```

### CLI 交互

```bash
# 查询当前 Tier 和有效强度矩阵
mumuspec constraints resolve --show-model-tier

# 输出示例：
# Active Model Tier: A (auto-detected from $MUMUSPEC_MODEL_ID)
# ┌───────────────────┬─────────┬────────────┬───────────┐
# │ Dimension         │ Baseline│ Tier Delta │ Effective │
# ├───────────────────┼─────────┼────────────┼───────────┤
# │ technical_design  │ medium  │    0       │ medium    │
# │ requirement_goals │ high    │    0       │ high      │
# └───────────────────┴─────────┴────────────┴───────────┘
# Exceptions: 12 constraints always enforced (regardless of Tier)

# 手动指定 Tier 运行（覆盖 auto_detect）
mumuspec loop --model-tier B
mumuspec review --model-tier S

# 验证用：在特定 Tier 下求值约束集
mumuspec constraints evaluate --tier S
mumuspec constraints evaluate --tier C
```

## 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| Tier 定义主观（同一模型不同场景能力不同） | 高 | 中 | model_map 允许精确覆盖 + 明确标注"仅供参考" |
| 旧版本 config.yaml 无 `model_tier` 段落 | 高 | 低 | 默认 fallback 到 Tier=A（不调制） |
| 用户刻意用 S-Tier 绕过关键约束 | 中 | 高 | 例外清单不可降级；`disable_modulation` 补救；审计日志记录 Tier 决策 |
| auto_detect 失败时无友好提示 | 中 | 低 | 检测失败 → WARN + 默认 A + 提示用户手动指定 |
| 模型版本号变化导致 model_map 失效 | 中 | 低 | 前缀匹配 (`claude-sonnet-4` → `claude-sonnet-4-*`) |
| 与 R-0010 Meta-Spec Evolution 的 effectiveness_score 耦合 | 低 | 中 | Meta-Spec 评分按"约束条目"不随 Tier 浮动 |
