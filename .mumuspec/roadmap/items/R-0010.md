# R-0010: 统一 DSL 语言规范 v1

## 背景

> 为什么需要这个目标？当前痛点是什么？不做的后果？

DSL 定位已裁决（knowledge KP-0059：持久化 spec 是一门带 verifier 的领域特定语言，不是字节码式 IR）。但当前语法面散落在 parser 约定（src/spec/parser.ts）、validator 逻辑、design-schema.yaml 与设计文档之间，**没有单一的语言规范文档**；spec.md/prd/tech 与 constraints.yaml 双轨表达靠单向派生维系；P0 提案遗留的结构化 enforcement 引用（test:/command:）与树分层 strict 门控未落地。不做的后果：语言持续演化而无冻结点，每次实现改动都可能无声破坏存量 spec（本次 round-trip 丢字段即预演）。

## 范围

### 包含（Includes）
- **grammar**：Requirement 块 / SHALL·SHALL NOT·SHOULD·Enforcement 节 / `manual(原因)` 保留字 / frontmatter（layer/scope/prohibitions annotation）/ constraints.yaml 条目 schema 的冻结定义
- **semantics**：极性 × 维度 × 强度 × 可验证性四分类判定规则收编（constraint-strength.md §9.0 为基础，统一成语言语义章）
- **diagnostics**：E-SPEC-*/E-VERIFY-* 错误码作为编译诊断的正式定位（含 fixSteps 即修复指引）
- 结构化 enforcement 引用语法：`test:<suite>` / `command:<cmd>`（含 TS provider 最小执行实现——P0 提案 N1 的解冻）
- `enforcement_strict` 树分层收紧（子层可收紧不可放宽，提案 D1 遗留）
- RG 维度验收条件的 EARS 化指引（`WHEN ... THE SYSTEM SHALL ...` 可提取句式）
- spec.md 双轨收敛路径：constraints.yaml 条目为唯一机器面，Markdown 为渲染视图（sync 工具化）

### 不包含（Excludes）
- 存量 spec 的全量迁移（只定义规范与迁移工具路径）
- tree-sitter 多语言 AST provider（独立立项，R-0003 已完成的框架上扩展）

## 验收标准（DoD）
