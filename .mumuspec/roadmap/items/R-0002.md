# R-0002: Loop 自动化评估

## 背景

> 当前 Loop 模式的收敛判断完全依赖人工输入 `progress` 和 `goal_achieved`，缺乏自动化指标驱动的收敛判断能力。
> DGM（Sakana AI）通过经验验证在 SWE-bench 实现 20%→50% 跃升的核心就是自动化收敛判断。

## 依赖说明（Dependency Rationale）

- `R-0003`（AST-based Guard）：语义级约束检测是采集 "drift score" 和 "spec compliance rate" 的技术基础。没有 AST 分析能力，正则只能做"是否包含某字符串"的粗粒度检测，无法评估"设计模式合规性"等深层指标。

## 范围

### 包含（Includes）
- **指标采集模块** — test pass rate、drift score、spec compliance rate、code delta ratio
- **`auto-evaluate` 模式** — 基于指标阈值自动判断收敛（替代人工 goal_achieved 输入）
- **`hybrid-evaluate` 模式** — 客观指标为主（70% 权重）+ 人工确认为辅（30% 权重）
- **评估报告 HTML 导出** — 每轮指标变化趋势可视化
- **与 `detectStagnation()` 深度整合** — 自动回退机制

### 不包含（Excludes）
- 基于 LLM-as-Judge 的主观质量评估（过于主观，不稳定）
- 跨变更基准对比（需要数据积累，留作后续）
- 完全无人值守的 CI/CD 自动化循环（长期愿景）

## 关键设计决策

**指标阈值保守初始值**：初始阈值设置偏保守（避免虚假收敛），允许通过 `mumuspec loop config` 微调。

**evaluator chain 可插拔**：每个指标采集器实现 `Evaluator` 接口，可按需启用/禁用。

## 验收标准（DoD）

| # | 验收条件 | 验证方法 |
|---|---------|---------|
| 1 | `--auto-evaluate` 基于客观指标自动收敛 | 给定阈值后 3 轮内宣布完成 |
| 2 | 连续 3 轮指标达标时自动 progress=1.0 | 连续 3 轮达标后 phase=converged |
| 3 | `--hybrid-evaluate` 人工可覆盖自动判断 | 手动 goal_achieved=true 立即收敛 |
| 4 | HTML 报告包含 test/drift/compliance 趋势图 | 输出文件包含 SVG/Canvas 图表 |
| 5 | 与现有 `detectStagnation()` 联动 | 回退触发时 reuse 标准 Rollback 流程 |
| 6 | 至少 8 个单元测试覆盖评估逻辑 | vitest 测试通过 |

## 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 指标阈值过松导致虚假收敛 | 中 | 高 | 保守初始阈值 + 允许用户微调 |
| 指标采集性能开销 | 低 | 中 | 异步采集 + 按需启用 |
| AST 检测对 R-0003 实现的依赖风险 | 中 | 高 | 定义清晰接口，R-0002 用 mock 先行开发 |
