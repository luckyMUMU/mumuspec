# R-0008: AST-based Guard 升级

## 背景

> 当前 Guard Layer 的 `checkProhibitionViolation()` 大量依赖正则模式匹配，
> 对"禁止可变状态""函数必须保持幂等""不得引入循环依赖"等深层语义约束几乎无效。
> 调研表明：企业级合规场景（设计模式约束、性能模式约束）需要语义级检测能力。
> 竞品 ESLint Plugin 体系、Tree-sitter 查询已在 AST 检测上成熟应用，MumuSpec 需跟进。

## 范围

### 包含（Includes）
- 引入 TypeScript Compiler API 替换高频语义约束的正则实现
- `parser` 字段区分正则规则 vs AST 规则，使开发者理解不同约束的检测可靠性
- 保留正则实现用于"禁止引入新依赖"等已足够准确的结构性约束
- `STRENGTH_ACTION_MAP` 中新增 `parser: 'regex' | 'ast'` 元数据
- 高频 P0 约束优先迁移（约 5-8 条）

### 不包含（Excludes）
- 完全替换所有正则规则（结构性约束保留正则更高效）
- 跨语言 AST 分析（仅 TypeScript 先行）
- 自定义约束 DSL（过度设计）

## 验收标准（DoD）

| # | 验收条件 | 验证方法 |
|---|---------|---------|
| 1 | "禁止可变状态"约束在 let 重新赋值时触发 | 测试用例通过 |
| 2 | "强制幂等"约束在函数有副作用时触发 | 测试用例通过 |
| 3 | "不得循环依赖"在模块间循环引用时触发 | 测试用例通过 |
| 4 | 正则约束仍正常工作（禁止 import 某模块） | 回归测试通过 |
| 5 | 规则包含 `parser` 字段标识检测方式 | frontmatter 校验通过 |
| 6 | AST 检测性能不劣于正则 3 倍以上 | 基准测试报告 |

| 风险 | 概率 | 影响 | 缓解措施 |
