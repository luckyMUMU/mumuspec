# R-0006: Contract Registry 标准化

## 背景

> 当前没有行业标准定义"AI 编程工具应该如何检测规范与代码的不一致性"。
> MumuSpec 的 6 类契约漂移检测是事实上的标准草案，有机会推动为 IDE/DevTool 行业共同实践（类似 ESLint 对 JS linting 的标准化效应）。

## 范围

### 包含（Includes）
- **Contract Registry JSON Schema 标准化文档** — 机器可读的契约格式定义（ajv 可校验）
- **IDE-compatible 漂移检测报告格式** — 兼容 VS Code Problem Matcher / ESLint Stylish / SARIF
- **MCP 协议标准化提案** — 向 MCP 工作组提交 Guard/Drift 工具 Schema proposal
- **Contract Impact Analysis 审计报告导出** — PDF + HTML 合规报告（金融/医疗行业适配）
- **Audit Log 跨变更聚合分析** — 时间线视图 + 决策热力图 HTML Dashboard
- **ESLint Plugin 互操作适配** — 将 Mumuspec 约束以 ESLint 规则形式输出

### 不包含（Excludes）
- 创立新标准组织（先贡献现有开源标准）
- 跨语言统一契约格式（TypeScript 生态先行）
- 商业化审计功能（保持开源基础能力）

## 关键设计决策

**IDE 兼容先行**：漂移报告格式兼容 SARIF（Static Analysis Results Interoperability Format），所有主流 IDE/CI 无需额外适配。

**标准先行于功能**：先发布 JSON Schema 和 proposal 文档，再实现高级功能（PDF 导出、聚合分析）。

## 验收标准（DoD）

| # | 验收条件 | 验证方法 |
|---|---------|---------|
| 1 | Contract Registry JSON Schema 发布（ajv 校验通过） | schema 文档可通过 ajv 校验样本 |
| 2 | 漂移检测报告输出 SARIF / Problem Matcher 格式 | VS Code 扩展可原生消费报告 |
| 3 | MCP Tool Schema 标准化 proposal 文档完成 | 完整 proposal markdown |
| 4 | Contract Impact Analysis 支持 PDF/HTML 导出 | 给定变更范围生成审计报告 |
| 5 | Audit Log 支持跨变更聚合分析（时间线 + 热力图） | HTML Dashboard 输出 |
| 6 | 至少 1 篇正式 MCP 工作组提案发布提交 | 文档或 GitHub Discussion |
