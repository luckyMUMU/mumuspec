# R-0003: AST-based Guard 升级 — 多语言可扩展语义检测

## 背景

> 当前 Guard Layer 的 `checkProhibitionViolation()` 大量依赖正则模式匹配，对"禁止可变状态""函数必须保持幂等""不得引入循环依赖"等深层语义约束无效。
> 企业级合规场景（设计模式约束、性能模式约束）需要语义级检测能力。
> **进化目标**：在原 TypeScript Compiler API 基础上，构建**主流语言可扩展的 AST Provider Registry**，让 Guard 不仅限于 TS/JS，还能覆盖 Python、Java、Go 等主流语言的语义约束检测。

## 范围

### 包含（Includes）
- **`src/guard/ast-engine.ts`** — 重构为多语言 AST 引擎核心：
  - `ILanguageProvider` 接口定义
  - `LanguageProviderRegistry` 注册中心（支持运行时动态注册新语言 Provider）
  - TypeScript Provider（使用 TS Compiler API）
  - JavaScript Provider（复用 TS Provider）
  - Python Provider 骨架（用 Python AST via subprocess 或 tree-sitter 实现）
  - Provider 自动发现路由机制
- **`src/guard/checker.ts`** 升级 — 根据文件扩展名自动选择 Provider
- **`parser` 字段增强** — `parser: 'regex' | 'ast-ts' | 'ast-py' | 'ast-java' | 'ast-go'` 支持语言标识
- **Provider 注册 API**：
  - `registerLanguageProvider(ext: string, provider: ILanguageProvider)` — 公共 API
  - `getLanguageProvider(ext: string)` — 查询 API
  - `listProviders(): string[]` — 列出所有已注册语言
- **高频 P0 约束优先迁移**（5-8 条 TS/JS）：
  1. 禁止可变状态（let/var 重新赋值检测）
  2. 强制幂等（函数副作用检测 — 外部赋值/IO 调用）
  3. 禁止循环依赖（模块间 import 环检测）
  4. 设计模式合规性（class 结构约束 — 工厂/单例等）
  5. 异步操作完整性（async/await 配对检测、Promise 链完整性）
- **Architecture Decision**:
  - 不引入 tree-sitter（初始）— 保持依赖最小化
  - 使用 TypeScript Compiler API 处理 TS/JS
  - Python 通过内置 `ast` 模块 + subprocess 调用（`python3 -c "...")`）
  - Provider 接口设计兼容未来引入 tree-sitter

### 不包含（Excludes）
- 完全替换所有正则规则（结构性约束保留正则更高效）
- 自定义约束 DSL（YAGNI — 过度设计）
- AST 可视化调试器（IDE 功能，与 Guard 运行时无关）
- Java/Go 的初始完整实现（明确为后续扩展点）

## 可扩展性设计（Extensibility Blueprint）

```typescript
// ILanguageProvider — 所有语言 Provider 实现此接口
interface ILanguageProvider {
  readonly language: string;       // 'typescript' | 'python' | 'java' | ...
  readonly extensions: string[];   // ['.ts', '.tsx'] | ['.py'] | ...
  
  /// 解析源码为 AST（内部格式）
  parse(source: string, filename: string): ASTResult;
  
  /// 检查语义约束
  checkConstraint(
    ast: ASTResult,
    constraint: SemanticConstraint,
  ): ConstraintViolation[];
  
  /// 可选：提供语言特定格式化
  formatMessage(violation: ConstraintViolation): string;
}

// Provider 注册 — 第三方（或 MumuSpec 自身）通过这些 API 扩展
export function registerLanguageProvider(provider: ILanguageProvider): void;
export function unregisterLanguageProvider(language: string): boolean;
export function getLanguageProvider(ext: string): ILanguageProvider | null;
export function getAvailableProviders(): ProviderInfo[];

// 新增语言 Provider 的步骤：
// 1. 实现 ILanguageProvider 接口
// 2. 调用 registerLanguageProvider(new MyProvider())
// 3. Guard 自动路由到该 Provider 处理对应扩展名
```

### 三阶段扩展路线图

| Phase | 能力 | Provider 实现 |
|-------|------|--------------|
| P0 (本 Item) | TS/JS 语义检测 | TypeScriptProvider (Compiler API) |
| P1 (后续) | Python 检测 | PythonProvider (ast + subprocess) |
| P2 (后续) | Java/Go/Rust | 支持 tree-sitter 或语言原生工具 |

## 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| TS Compiler API 在 monorepo 配置下解析失败 | 中 | 中 | fallback 到 regex + 日志告警 |
| Provider 路由性能开销 | 中 | 低 | Provider 注册表缓存 + 懒加载 |
| 第三方/社区 Provider 质量不稳定 | 中 | 中 | Provider 沙箱化 + 错误隔离 |
| Python subprocess 调用失败率高 | 高 | 低 | P1 阶段实现，当前仅预留接口 |
| 语义约束误报率过高 | 中 | 高 | 保守阈值 + warn 级别先行 + 用户可 tune |
